## How to trigger a jenkins job via cli and remote trigger endpoint.

```bash
curl -X POST \
  "$JENKINS_URL/job/playground/job/jenkins-test/buildWithParameters?token=<PIPELINE_TOKEN>&<PIPELINE_PARAMS>=<PIPELINE_PARAMS_VALUES>" \
  --user "<USERNAME>:<MY_API_TOKEN>"
```

### Alternative with crumbs and cookie

```bash
# --- Config ---
JOB_PATH="<JOB_PATH>"

# Pipeline parameters
PARAM_ONE="one"
PARAM_TWO="two"

# --- Setup ---
COOKIE_JAR="$(mktemp)"
AUTH_HEADER=$(printf "%s:%s" "$JENKINS_USER" "$JENKINS_TOKEN" | base64 | tr -d '\n')

# --- Fetch crumb ---
CRUMB_JSON=$(
  curl -sS -c "$COOKIE_JAR" \
    -H "Authorization: Basic $AUTH_HEADER" \
    "$JENKINS_URL/crumbIssuer/api/json"
)
CRUMB_FIELD=$(jq -r '.crumbRequestField' <<<"$CRUMB_JSON")
CRUMB_VALUE=$(jq -r '.crumb' <<<"$CRUMB_JSON")

echo "✓ Got crumb: $CRUMB_FIELD=$CRUMB_VALUE"
echo "✓ Cookies saved in $COOKIE_JAR"

# --- Variant A: JSON payload to /build ---
BUILD_URL="$JENKINS_URL/job/<JOB_PATH>/build"
JSON_PAYLOAD=$(jq -n \
  --arg p1 "$PARAM_ONE" \
  --arg p2 "$PARAM_TWO" \
  '{parameter:[{name:"ONE",value:$p1},{name:"TWO",value:$p2}]}'
)

echo "→ Triggering build via JSON payload..."
curl -sS -o /dev/null -w "%{http_code}\n" \
  -b "$COOKIE_JAR" \
  -H "Authorization: Basic $AUTH_HEADER" \
  -H "$CRUMB_FIELD: $CRUMB_VALUE" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "json=$JSON_PAYLOAD" \
  "$BUILD_URL"

# --- Variant B: Simple form to /buildWithParameters ---
BUILD_WITH_PARAMS_URL="$JENKINS_URL/job/<JOB_PATH>/buildWithParameters"

echo "→ Triggering build via form parameters..."
curl -sS -o /dev/null -w "%{http_code}\n" \
  -b "$COOKIE_JAR" \
  -H "Authorization: Basic $AUTH_HEADER" \
  -H "$CRUMB_FIELD: $CRUMB_VALUE" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "ONE=$PARAM_ONE" \
  --data-urlencode "TWO=$PARAM_TWO" \
  "$BUILD_WITH_PARAMS_URL"

echo "✓ Done."

```

## How to get information about the jobs definitions

This is helpful if you need e.g. detailed information about the defined parameters of a job.

```bash
curl https://<JENKINS_URL>/jenkins/job/<JOB_URL_PART>/api/json?pretty=true
```

## How to handle secrets in strings securely

This pipeline script is an example on how to inject secrets that are stored in the user credentials provider.

```groovy
pipeline {
    agent none
    options {
        // Keep build history manageable for educational purposes
        buildDiscarder(logRotator(numToKeepStr: '10', daysToKeepStr: '2'))
    }
    parameters {
        /*
         * CREDENTIALS PARAMETER EXPLANATION:
         * 
         * This creates a dropdown in Jenkins UI showing available Username/Password credentials
         * from the user's credential store (personal), folder-level, or global Jenkins credentials.
         * 
         * Key points:
         * - Users can select from their own credential store
         * - The parameter name 'MY_SECRET_ID' becomes the credential ID to reference
         * - Works in Multibranch pipelines when triggered via UI or API
         * - Required: `true` means the build will fail if no credential is selected
         */
        credentials(
            name: 'MY_SECRET_ID',
            description: 'Select a Username/Password credential from your user store, folder, or global credentials',
            credentialType: 'com.cloudbees.plugins.credentials.impl.UsernamePasswordCredentialsImpl',
            required: true
        )
    }
    stages {
        stage('Method 1: Stage-Level Environment Block') {
        agent { node { label 'master' } }

            /*
             * STAGE-LEVEL CREDENTIAL BINDING:
             * 
             * Using 'environment' block at stage level automatically:
             * - Binds the selected credential for this stage only
             * - Creates two variables: CREDS_USR (username) and CREDS_PSW (password)
             * - Password is automatically masked in Jenkins console logs (shows as ****)
             * - Scope is limited to this specific stage
             */
            environment {
                CREDS = credentials('MY_SECRET_ID')  // References the parameter name directly
            }
            steps {
                echo "=== DEMONSTRATING STAGE-LEVEL CREDENTIAL BINDING ==="
                echo "This method uses Declarative Pipeline's environment block"
                echo "Variables created automatically: CREDS_USR and CREDS_PSW"
                echo ""
                sh '''
                    echo "  Credential Information:"
                    echo "  Username: $CREDS_USR"
                    echo "  Password: $CREDS_PSW"  # This will appear as **** in logs (SECURE)
                    echo ""
                '''
            }
        }
        stage('Method 2: withCredentials Block') {
            agent { node { label 'master' } }
            steps {
                echo "=== DEMONSTRATING withCredentials BLOCK ==="
                echo "This method provides more control"
                echo ""
                script {
                    /*
                     * withCredentials BLOCK EXPLANATION:
                     * 
                     * This is the more flexible and recommended approach:
                     * - Explicitly defines variable names (USERNAME_VAR for username, PASSWORD_VAR for password)
                     * - Can be used within script blocks for complex logic
                     * - Credentials are automatically masked in logs
                     * - Scope is limited to the withCredentials block only
                     * - Works with both Declarative and Scripted pipelines
                     * 
                     * IMPORTANT: This wont work with the user scoped credentials in Multibranch pipelines
                     */
                    withCredentials([
                        usernamePassword(
                            credentialsId: 'MY_SECRET_ID', // Parameter name from above
                            usernameVariable: 'USERNAME_VAR', // Custom username variable name
                            passwordVariable: 'PASSWORD_VAR'           // Custom password variable name
                        )
                    ]) {
                        sh '''
                            echo "  Credential Information (Custom Variables):"
                            echo "  Custom Username Variable: $USERNAME_VAR"
                            echo "  Custom Password Variable: $PASSWORD_VAR"  # Masked as ****
                            echo ""
                        '''
                    }
                }
            }
        }
    }
}
```

## How to run all multibranch pipelines in a given folder

Using this in the script console of Jenkins will trigger all pipelines in that given folder.

```groovy
import org.jenkinsci.plugins.workflow.multibranch.WorkflowMultiBranchProject
import hudson.model.Cause.UserIdCause

Jenkins.instance.getAllItems(WorkflowMultiBranchProject.class).findAll {
    return it.fullName =~ '^folder/subfolder/'
}.each {
    it.scheduleBuild(0, new UserIdCause())
}
```
